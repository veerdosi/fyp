# Decision after two matched pose-feasibility pairs

Retire the optional structured pose query from the current research allocation.
The runnable implementation and every scheduled outcome remain retained. Do not
spend on another query threshold, guard variant or replacement start.

The prospective failure criterion was no observed change in unsupported pose
choices and no paired task/resource benefit. Baseline completed 1/2; preview 0/2.
Each preview queried two solved poses once and reached its queried approach.
Neither received a no-solution warning. The warning-avoidance pathway did not
engage, so this does not falsify the usefulness of warnings when encountered.
It does fail to demonstrate contribution from making this query available here.

Preview consumed more inference requests, simulated motion, native policy time
and API-equivalent cost on both starts. No pair jointly succeeded; no faster
completion or completion-resource ratio can be claimed. Start 2 had fewer
nonarriving preview waypoint exits but both conditions still failed placement.
That descriptive movement difference does not isolate a query effect.

All four episodes have exact replay, matched initial inputs/common execution,
usage exports, manual tool/calculation review and causal diagnosis. Two starts,
preview-first order in both pairs, stochastic decisions, interrupted host clocks
and the inability to independently compare encrypted initial dispatch plaintext
limit inference. Report the tested negative/null contribution without attributing
the entire outcome difference to the query or rejecting all H4 delegation.

The revised explanation separates three kinds of evidence. Empty-sized closure
can contradict an occupied-grasp expectation. A robot pose solution/arrival can
describe robot geometry. Neither establishes that an object was inserted or
released in the intended relation. The clean empty-interruption result remains
retained; it is not scheduled again under the name "grasp evidence."

The next necessary step is the [placement-error discriminator](next_test.md),
recorded before implementation. Use the five new public-data calculations and
their following motions to separate reference selection, attachment change and
contact-limited execution. Build no relation command until this identifies a
specific mechanism with an observable input and a credible matched baseline.
This is a zero-new-policy-call diagnosis of the completed batch, not another
tracker screen or another stopping experiment. The broader FYP remains active.
